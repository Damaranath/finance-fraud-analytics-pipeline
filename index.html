Finance & Fraud Analytics Pipeline

Featured project

An end-to-end fraud analytics pipeline for a simulated payments platform with 56,691 transactions, 5,000 customers and 400 merchants (synthetic data). It flags suspicious activity with rule-based fraud alerts, measures payment failures and chargeback exposure, and serves the results through Tableau dashboards and a REST API. A config-driven ingestion pipeline also loads 1.3M real card transactions from a public Kaggle dataset.

What I did

  • Designed a PostgreSQL database with separate core, risk and mart schemas, using constraints to keep the data valid.
  • Wrote four explainable fraud rules in SQL: high-value transactions, emulator devices, cross-border high-risk merchants and customers with repeat chargebacks.
  • Built the ETL flow: loaded raw data into PostgreSQL core tables, validated it, and transformed it into six SQL marts covering daily volumes, payment failures, chargebacks, suspicious activity, country risk and customer risk.
  • Built a config-driven, idempotent ingestion pipeline (Python + YAML to PostgreSQL) that loaded 1.3M real card transactions from a public Kaggle dataset with row-level validation and reject logging. Loaded plus rejected rows reconcile exactly to the source file, re-runs create zero duplicates, and the validation is verified with intentionally corrupted test data.
  • Ran data-quality checks and analysis in Python. I found and fixed a one-to-many join that was inflating results.
  • Built a FastAPI REST API with a live dashboard. A reconciliation check found 2,813 transactions missing from the status breakdown, which I fixed.

Organ Disease Progression Visualizer

Master's team project · 5 members

A pipeline that turns chest CT scans into interactive 3D lung models showing how pulmonary fibrosis progresses. It extracts three disease signals from each scan (severity, texture and high-density ratio) and uses them to change the colour and shape of a 3D lung, from healthy through to advanced disease. Every change is written to a JSON audit log, so each visual can be traced back to the imaging evidence. We tested it on 8 patient cases.

My contribution

  • Co-developed the 3D disease prototype (prototype.py): anatomical weighting, deformation logic and tissue colouring.
  • Led the Blender evaluation. I tested materials, lighting and export, identified Blender's limitations, and drove the team's decision to move to a programmatic PyVista + Trimesh pipeline.
  • Integrated the audit logger into the pipeline, so every case records its extracted CT values, progression score, disease stage and model outputs.
  • Fixed mesh instability in severe cases by recalibrating the deformation constants, so the 3D mesh stopped tearing at high progression values.
  • Researched explainable AI and medical visualisation for the risks and significance analysis, and co-wrote the final report and presentation.

Team stack

  • Python
  • OpenCV
  • PyVista
  • Trimesh
  • Blender
  • JSON audit logs

Key decisions

  • Blender → PyVista (my evaluation): Blender looked more realistic, but material export problems, environment dependency and manual steps made it unusable for an automated, reproducible pipeline.
  • Language model → imaging signals: we first planned to drive the model from radiology reports, but the language model's outputs weren't reproducible, and clinical use needs every result to be traceable.

DP-MLM: Differentially Private Text Rewriting

Machine learning · NLP

I replicated DP-MLM (Findings of ACL 2024), a method that uses a masked language model (RoBERTa) to rewrite text with a formal differential-privacy guarantee. I then applied it to new data: AG News subsets and a synthetic dataset containing personal information (PII).

  • Python
  • PyTorch
  • Hugging Face Transformers
  • scikit-learn
  • NLTK

Result

At ε = 8, 67% of tokens were rewritten while TF-IDF similarity stayed at 0.86. Downstream classifier accuracy fell from 0.42 to 0.29 on a small test split, which measures the cost of the privacy.
